# 案件登錄與管制系統：架構與上線步驟（試跑版）

## 流程
分隊用計畫書產生器製作並通過檢核 → 按「📮 案件登錄」，資料自動帶入 → 補填後送出 → 取得案件編號（例 `115-成-0001`），寫在紙本上 →
大隊初審 → 業務科收件／發文 → 回覆進度 → 大隊核銷初審 → 業務科核銷複審 → 結案。被退回時由分隊修正後重送。

## 程式分層
| 檔案 | 用途 |
|---|---|
| `case_registry.py` | 欄位與階段定義、編號、驗證、權限、狀態判斷、異動紀錄；儲存層可換（MemoryStore／SheetStore） |
| `case_pages.py` | Streamlit 畫面：登入、案件總表、登錄新案件、處理案件、異動紀錄 |
| `app.py` | 只有 Secrets 設定了 `case_registry` 時，專區才出現「📮 案件登錄」分頁；產生器檢核無錯誤時把資料交給登錄單 |
| `tests/test_case_registry.py` | 編號、權限、階段順序、退回原因、階段鎖定、欄位對不上時拒寫 |
| `maintenance_auth.py` | 科內維護模式只接受 Secrets 的 `admin_password`，沒有設定就停用 |

## 試算表要求（明天建立）
- 「建立副本」現有表單回應表，**刪除所有資料列**，保留兩列標題。
- 在第 2 列最後面（AG 欄）新增標題「案件編號」。
- 工作表名稱預設「表單回應 1」。系統會逐欄核對標題，對不上就拒絕寫入。
- 「異動紀錄」工作表由系統自動建立。

## 帳號
- 第一次連線時，系統依組織架構在試算表建立「帳號」工作表，只存密碼雜湊，不存明碼。這也是備份：網站重新部署不會洗掉。
- 共 37 個帳號，帳號名稱就是單位名稱（臺、台都可）：4 個大隊、27 個分隊、6 個科室（民力訓練科、緊急救護科、資通作業科、災害搶救科、預防調查科、綜合企劃科）。
- 登入頁從清單選單位。順序是每個大隊緊接著自己的分隊，科室放在最後，開啟時不預選任何單位，也不公告初始密碼。
- 還沒改掉初始密碼（或被重設）的帳號，只能先改密碼，不能登錄、審核或使用計畫書產生器。新密碼只要不是空白、而且不能和初始密碼相同，沒有長度或字元種類限制。
- 忘記密碼：民力訓練科在「🔧 帳號管理」重設。重設後回到必須更改的狀態，暫時密碼請個別告知，不要貼在登入頁或群組。
- 密碼打錯只會顯示錯誤，不會鎖定帳號。「帳號」工作表維持原來 7 欄（帳號、角色、所屬大隊、單位、密碼雜湊、需更改密碼、更新時間），不加失敗次數或鎖定時間。案件主表也不加欄。
- 其他科室收件後，只有該科室看得到那件案子。民力訓練科不出現在別人的案件清單裡，但可以用案件編號開啟，代為做初審，或修改已經鎖定的前階段；這種修改的異動紀錄來源是「管理者覆核」。
- 科室帳號不能登錄新案件，只有分隊（及大隊本身）能登錄。大隊登錄時，所屬大隊鎖定為自己，不能代其他大隊的分隊送件。
- 沒有帳號：救災救護指揮中心、災害管理科、人事室、會計室、政風室，以及科技救災分隊、安檢隊（不屬任何大隊，送件方式待定）。

## 流程規則
- ② 申請初審只由該案所屬大隊辦理。其他科室不能跳過大隊直接初審。
- 退回分隊（申請初審或核銷初審）必須填退回原因。原因寫在「異動紀錄」，不寫進案件主表。分隊在案件頁面看得到原因，也看得到自己案件的異動紀錄。
- 「核准進度」只能選：審核中、已核准、未獲補助。「核銷進度」只能選：辦理中、已函發。選「已核准」才開放⑤，選「已函發」才結案。舊資料若寫成「核准」「已函文」，視同標準寫法，下次儲存會改成標準寫法；其他自由文字保留，不會因此往下走。
- 下一階段已經有資料時，前面的階段鎖定。只有民力訓練科可以改，並記入「管理者覆核」。備註與缺失登記不在這條鎖上。

## 尚待確認（目前是暫定值）
- 案件編號格式：年度三碼＋大隊單字代碼＋四碼流水號，台東＝台、關山＝關、成功＝成、大武＝武（只有這四個大隊）。
- 「補助款來源」欄的選項與寫法（目前帶入：議員／公所／議員、公所）。
- 「核准函是否回寄」仍是自由輸入。
